# Phase 2: identity assignment enrichment

The merged evaluation exports retain the original numeric Label Studio user IDs.
This optional step adds **assigned names** from a local, manually curated crosswalk
keyed by the judicial decision ID. It does not resolve or authenticate account
identities and does not alter spans, offsets, votes or labels.

Keep the crosswalk and enriched outputs under ignored local data folders; never
commit them to this public repository. The crosswalk must be reviewed against
the evaluator assignment records before trusting its names.

Expected local crosswalk CSV headers:

```text
id_acordao,anotador,avaliador_projeto_1,avaliador_projeto_2,projeto_1_id_confirmado,projeto_2_id_confirmado
```

Example run on the **JSON output** of the earlier merge, in PowerShell:

```powershell
python -m legal_nlp.phase2_identity_enrichment `
  --input "data/interim/phase_2/merged_evaluations.json" `
  --crosswalk "data/raw/phase_2/identity_crosswalk.csv" `
  --output "data/interim/phase_2/merged_evaluations_enriched.json" `
  --report "data/interim/phase_2/identity_enrichment_report.json" `
  --strict
```

The strict option rejects missing or unmatched decision IDs. It is not a
verification of the mapping between numeric Label Studio user IDs and names.

To export the flat CSV generated by `legal_nlp.phase2_csv`, run the same
command with CSV input and output paths. Nested JSON is preserved in JSON;
export a companion CSV through the existing `phase2_csv` module when needed.

All names in automated tests are invented; tests contain no judicial records.
